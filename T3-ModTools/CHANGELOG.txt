T3-MODTOOLS CHANGELOG
=====================================

0.6.12 maintenance - 2026-11-03
------------------------------
- Fix Generate mod pack validation for enabled animation mods: analyze the staged
  pack against read-only installed COD archives and pass the compatibility plan
  to the isolated loader validator, including any automatically required AI target.
- Migrate exact verified legacy ANM patches before renaming pack patch IDs, avoiding
  obsolete writes conflicting with current automatic animation/SFX support.
- Preserve the resolved NPC animation variant configuration in the pack and record
  legacy migration and configuration provenance in MERGE_REPORT.json.
- Add regression coverage for archive context, automatic AI inputs, legacy safety,
  animation configuration, priority, and failed-publication isolation.

0.6.12 - 2026-10-28
------------------
- Recognize the private Heavy WM32 dual running role as a WM20 TPS channel
  reference, preserving automatic UPDOWN composition when compiling its clip.

0.6.11 - 2026-10-22
------------------
- Declare required mods in mod.json: toggling a base mod updates its dependents,
  enabling a dependent enables installed prerequisites, and old invalid selections
  are repaired without changing priority.
- Compile disabled custom weapon entries out of the menu without overwriting
  authored Weapons.dat files. Build reports list omitted weapon keys.
- Enhanced SFX now skips explicitly optional weapons absent from the enabled
  asset overlay, fixing builds with WM32 or Dual WM32 disabled.
0.6.10
------

- Runtime generators follow declared project dependencies before compiling,
  while visible mod priority continues to decide file winners. Cycles fail
  before any generator executes. Derived weapon models use the current export.
- Guarded loader_extension manifests place mod code in the owned read/execute
  .t3ldr section. Original fingerprints, bounded size, fixed addresses and
  non-overlap with other extensions and automatic animation code are checked.
- Supports Dual WM32's live wrist attachment and paired effects without adding
  offsets to authored weapon files.

0.6.9
-----

- Extended live audio diagnostics with channel/master volume, mute/pause flags
  and verified software-mixer gains after the WM27 live capture investigation.

- Added Live debug in Modding: timed, read-only technical captures of a running
  T3 1.16 match, with Ctrl+Shift+F9 to start/stop without changing game focus.
- Configurable duration, polling interval and F8/F9/F10/F11 global shortcut.
  Reports contain sampled weapons/ammo/fire requests, native sound state, recent
  queued events, assigned FMOD channels, build context and a bounded game log tail.
- Capture stops on timeout, manual stop, game exit, repeated read failures or
  128 MiB of samples. Partial reports are preserved. No video or audio recording,
  process writes or injected code. This does not change any weapon/audio mod.

0.6.8
-----

- Removed experimental normal-map discovery and renderer loading after in-game
  performance testing. Full builds retire its generated runtime transactionally.
- Preserved current animation compatibility and editable weapon asset pipelines.

0.6.6
-----

- Added t3_generated_assets.publish_generated_assets for runtime generators that
  export Blender models, textures, locators and executable manifests together.
  It preserves files/ directory identities, avoiding Windows directory-rename
  access errors. Unchanged files are skipped; changed files are replaced with
  rollback if publication fails. Only previously tracked generated files are
  removed when obsolete, preserving unrelated user additions.
- Projects can declare generates_assets: true in mod.json. Rebuild Modded EXE
  then performs a complete package/executable build, so regenerated muzzle
  coordinates and model assets cannot be left out of Mods.Cod.
- Migrated WM-32's generator to the shared publisher. Saved Blender empties
  continue to drive the primary/secondary locators without changing their math.

0.6.5
-----

- Updated the Blender ANM exporter to 0.7.0: per-Action Walk Animation checkbox,
  Timeline/Dope Sheet footstep context-menu entries, editable Action-local footstep
  markers, and AnimationNotify export with zero-based frame alignment and validation.
- Renamed Create mod pack to Generate mod pack, keeping it below Create mod in Modding
  mode and updating its English, Spanish, Russian, and Portuguese labels.
- Console messages now follow the selected interface language.
- Raw runtime-generator output and technical error details are saved as diagnostic logs
  under modtools_data/logs/ or the extraction output's logs/ folder, with a localized
  result and diagnostic path in the console. Third-party prose is preserved in the logs.
- Moved load_order.json, Mods.Cod, and .compiled/ build reports into modtools_data/ inside
  the game installation, keeping the mods folder for user projects.
- Added recoverable migration of existing mod state and generated files from the old
  locations, preserving enabled states and visible order, with exact backups under
  modtools_data/legacy_backup/. Existing destination data takes priority over old copies.
- Custom mods folders retain separate load orders under modtools_data/load_orders/.
- Updated the generated loader to read modtools_data/Mods.Cod.
- Corrected a crash in the initial 0.6.5 implementation: enlarging the loader path and
  marker in .data overwrote a live empty-string sentinel used by the menu. The version
  remains 0.6.5; loader code and data now occupy a dedicated appended .t3ldr RX section.
- Recognized older loaders are verified using their bytes and manifest fingerprints.
  Migration restores their original storage and installs the corrected loader while
  preserving the last build's mod patches.
- Launch requires the dedicated-section loader. Unrecognized older executables retain
  their legacy archive and require Build Mods + Modded EXE with the intended mods enabled
  before launch; a successful build retires that archive.

0.6.1.4
-------

- Added Create mod pack directly below Create mod in Modding mode, localized in English,
  Spanish, Russian, and Portuguese.
- Packs include only enabled mods and preserve top-first asset priority, with consistent
  directory casing and a merge report identifying file owners, hashes, and patch sources.
- Runtime generators are synchronized before freezing executable patches into a standalone
  manifest. Per-patch targets are retained and patch IDs are made unique.
- Patch validation uses isolated copies of T3.exe and Ai.Dll, including loader conflicts;
  incompatible writes stop creation. Identical overlapping writes remain valid.
- Pack creation runs in the background and publishes only after copying and validation
  succeed. The completed pack is enabled, source mods are disabled, and their folders remain.
- Added rollback, priority, generator, path, naming, and real-binary equivalence coverage.

0.6.1.3
-------

- Executable patch format v1 now accepts T3.exe or Ai.Dll per patch.
- Ai.Dll patches generate A2.Dll from the pristine original and redirect only
  T3_Modded.exe to that generated copy; neither original binary is overwritten.
- Build rollback now treats A2.Dll as part of the generated output set.
- AOB matching is anchored to the longest concrete byte run, avoiding slow Python-wide
  scans for every signature when multiple binaries are patched.
- Build logs and loader_manifest.json record the target binary for each applied patch.

0.6.1.2
-------

- Build Mods + Modded EXE now detects root-level runtime_patch.py generators in enabled
  projects and runs each one with --write before compiling executable.json.
- Runtime generators use the same Python interpreter as T3-ModTools, execute without a
  command shell or a visible Windows console, and are limited to 60 seconds.
- Disabled project generators are never executed.
- Generated executable manifests are parsed and validated before any previous Mods.Cod or
  T3_Modded.exe output is staged, so synchronization failures leave the valid pair intact.
- Added regression tests for successful synchronization, disabled generators, failure
  rollback safety, and the 0.6.1.2 application version.

0.6.1.1
-------

- Added complete Russian and Portuguese translations for Asset Extraction and Modding modes.
- Added Russian and Portuguese to the persistent language selector.
- Added automated localization checks for supported languages, translation keys, and
  dynamic message placeholders.
- Renamed T3_Frame_Per_Bone_exporter.py to T3_Transform_Converter.py and updated
  its internal add-on, panel, operator, settings, report, and text-block names.
- Updated T3 Transform Converter to version 2.0.0, replacing the removed Blender
  5.x Bone.select API with context-based pose-bone selection, allowing F0-to-F0
  TXT reports to import their single absolute pose value as a keyframe, and adding
  an optional mathematically consistent X mirror for exported poses.


0.6.1
-----

- Changed mod conflict resolution so the enabled mod highest in the visible load order
  has priority when multiple projects provide the same internal file.
- Kept load_order.json in the same top-to-bottom order shown by the interface.
- Clarified the priority direction in the English and Spanish interface and documentation.


0.6.0
-----

- Renamed the application to T3-ModTools.
- Renamed the Windows launchers to T3-ModTools.bat and T3-ModTools.vbs.
- Added automatic migration support for the previous T3 Asset Tool settings location.
- Added patches/executable.json support to each mod project.
- Added safe AOB executable patch manifests with wildcards and expected-match validation.
- Added executable patch conflict detection; incompatible overlapping writes stop the build.
- Changed the main mod build action to rebuild both Mods.Cod and T3_Modded.exe automatically.
- T3_Modded.exe is always regenerated from the pristine original T3.exe; T3.exe remains untouched.
- Added support for executable-only mods by generating a valid empty Mods.Cod when needed.
- Mod project details now show both packaged file count and executable patch count.
- Build backups now use unique transaction names so stale or temporarily locked backups
  cannot block later builds, with rollback also covering failures during backup staging.
- Mod builds now remove the previous load_order.json and recreate it from the current
  project order and enabled state, alongside cleaning Mods.Cod and mods/.compiled/.

0.4.3
-----

- Updated the UV option label to warn that it should not be used with glTF 2.0 models.
- Made rigged glTF export preserve the source UV V coordinate regardless of the OBJ UV-flip checkbox.
- Removed the redundant global triangle reversal from mirrored glTF rigs.

- Added per-triangle winding repair when source triangle order conflicts with stored vertex normals.
- Explicitly marked rig materials as OPAQUE and single-sided to prevent texture alpha from being interpreted as general transparency.
- Kept OBJ winding behavior unchanged.
